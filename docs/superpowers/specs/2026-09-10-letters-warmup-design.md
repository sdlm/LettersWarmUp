# LettersWarmUp — дизайн

Дата: 2026-09-10

## Цель

Мини web-app для повторения алфавита с ребёнком. Показывает буквы в случайном
порядке, ребёнок отвечает «знаю» / «не знаю». Следующая буква выбирается
случайно с весами: буквы, которые ребёнок не знает, возвращаются чаще.

На выходе — **один самодостаточный HTML-файл** (`dist/index.html`), который можно
скинуть на телефон и открыть с локального диска, без сервера и без сети.

## Ключевые решения

| Вопрос | Решение |
|---|---|
| `k` для буквы, не показанной в сессии | `1` (нейтральный) |
| Что переживает перезагрузку | Только настройки (алфавит, тема). История ответов — нет |
| Регистр букв | Только заглавные |
| Русский алфавит | 32 буквы, без `Ё` |
| Экраны | Один экран, переключатели строкой сверху |
| Таймер на нуле | Гаснет (цифра исчезает) |
| Тема | Только ручной тумблер, старт со светлой, системная настройка игнорируется |
| Организация кода | Модули в `src/`, сборка в один файл через `build.py` |

## `scheduler.js` — логика выбора буквы

Единственное место с нетривиальной логикой. Все функции чистые: время (`nowMs`) и
генератор случайных чисел (`rng`) передаются аргументами, поэтому тесты
детерминированы.

### Состояние сессии

Обычный объект, свой для каждого алфавита:

```js
{
  history: { "Ж": { answer: "know", closedAt: 1757500000000 } },
  lastShown: "Ж"
}
```

- `history` — только буквы, на которые уже был дан ответ в этой сессии.
- `closedAt` — момент нажатия кнопки ответа (мс, `Date.now()`).
- `answer` — `"know"` или `"dont_know"`.
- `lastShown` — буква, показанная последней, или `null` в начале сессии.

### API

```js
createSession()                              // -> state
recordAnswer(state, letter, answer, nowMs)   // мутирует history и lastShown
computeWeights(state, letters, nowMs)        // -> [{ letter, t, k, w }]
pickNext(state, letters, nowMs, rng)         // -> letter
```

`rng` — функция без аргументов, возвращающая число в `[0, 1)`. В приложении это
`Math.random`, в тестах — заглушка.

### Правила расчёта

Для каждой буквы алфавита:

| Случай | `t` (секунды) | `k` |
|---|---|---|
| буква показана последней (`letter === state.lastShown`) | `0` | `1` (не влияет, `w = 0`) |
| буквы нет в `history` | `300` | `1` |
| в `history`, ответ был «знаю» | `(nowMs − closedAt) / 1000` | `0.5` |
| в `history`, ответ был «не знаю» | `(nowMs − closedAt) / 1000` | `2` |

Проверка `lastShown` имеет приоритет над остальными: буква, показанная
последней, всегда получает `t = 0`, даже если она есть в `history`.

`w = t · k`. Вероятность выпадения буквы — `w / Σw`.

`t` — число с плавающей точкой, не округляется, но **обрезается снизу нулём**:
`t = max(0, (nowMs − closedAt) / 1000)`. Без этого переведённые назад часы
(коррекция по NTP, ребёнок в настройках даты) делают все веса отрицательными:
`Σw ≠ 0`, поэтому аварийная ветка не срабатывает, `pickNext` возвращает `null`,
а распределение схлопывается на одну букву — причём недоступной становится
самая трудная. Обрезка ничего не меняет при корректных часах.

### Следствия по поведению

- Новая буква даёт `w = 300`; буква с ответом «не знаю» минуту назад — `w = 120`,
  поэтому **в начале сессии новые буквы заметно перевешивают**. Но вес повтора
  растёт линейно со временем: при ~6 сек на букву буква с ответом «не знаю»
  догоняет вес новой примерно к 25-му показу, и дальше повторы конкурируют
  наравне. Замер на симуляции сессии в 200 показов (RU, 32 буквы): все буквы
  успевают показаться за ~64 показа, повторов подряд — ноль, трудные буквы
  выпадают в ~1.6 раза чаще лёгких.
- Буква с ответом «не знаю» возвращается вчетверо быстрее, чем с ответом «знаю».
- Только что показанная буква не может повториться подряд (`w = 0`) — на
  взвешенной ветке. Равномерная страховка при `Σw = 0` выбирает из всех букв
  без исключения `lastShown`, но эта ветка достижима только когда все веса
  обнулены, поэтому исключение оставлено как есть.
- Первый ход сессии: истории нет, `lastShown = null`, у всех букв `w = 300` —
  равномерный случайный выбор.

### Алгоритм `pickNext`

1. Посчитать веса через `computeWeights`.
2. `total = Σw`.
3. Если `total === 0` — вернуть случайную букву равномерно. Страховка;
   достижимо при алфавите из одной буквы, а также если часы переведены
   назад и все буквы уже отвечены (тогда клэмп обнуляет все веса).
4. Иначе: `r = rng() * total`, идти по буквам в порядке алфавита, вычитая `w`,
   вернуть первую букву, на которой накопленная сумма превысила `r`.
5. Из-за погрешности с плавающей точкой цикл может дойти до конца — тогда
   вернуть последнюю букву с ненулевым весом.

## `app.js` — поведение приложения

### Состояние в памяти

- Отдельная сессия (`createSession()`) на каждый алфавит, создаётся лениво.
  Переключение алфавита не стирает историю другого.
- Обе сессии живут только пока открыта страница; перезагрузка сбрасывает их.

### Таймер

- 5 секунд, сбрасывается при показе каждой новой буквы.
- Отображает целые секунды: `5, 4, 3, 2, 1`, на нуле цифра исчезает.
  Скрывать через `visibility: hidden` (не `display: none` и не атрибут
  `hidden`) — место под цифру должно остаться зарезервировано, иначе буква
  прыгнет при обнулении таймера.
- Реализация: запоминаем `startedAt`, `setInterval` 250 мс пересчитывает
  оставшееся из текущего времени. Это устойчиво к дрейфу и к сворачиванию
  вкладки — вернувшись через минуту, увидишь скрытый таймер, а не «5».
- По истечении таймера ничего не происходит: приложение ждёт нажатия кнопки.

### Взаимодействие

- Кнопка «Знаю» → `recordAnswer(state, letter, "know", Date.now())`, затем
  показать следующую букву.
- Кнопка «Не знаю» → то же с `"dont_know"`.
- Показ буквы: `pickNext(...)`, обновить DOM, перезапустить таймер.

### Настройки (localStorage)

- `lw.alphabet` — `"ru"` | `"en"`, по умолчанию `"ru"`.
- `lw.theme` — `"light"` | `"dark"`, по умолчанию `"light"`.
- Каждое чтение и запись обёрнуты в `try/catch`: в приватном режиме
  `localStorage` бросает исключение, приложение должно работать и без него.
- Переключение алфавита немедленно показывает букву из нового алфавита
  и перезапускает таймер.

## Вёрстка и стили

Mobile-first, ничего лишнего.

```
┌─────────────────────┐
│  RU  en          ☼  │   строка переключателей, приглушённая
│                     │
│                     │
│         Ж           │   буква, очень крупно
│                     │
│         3           │   таймер, мелко и приглушённо
│                     │
│ ┌───────┐ ┌───────┐ │
│ │ Знаю  │ │Не знаю│ │   крупные кнопки
│ └───────┘ └───────┘ │
└─────────────────────┘
```

- Разметка: три секции во флекс-колонке на `100dvh` — верхняя строка,
  растягивающийся центр (буква + таймер), нижний ряд кнопок.
- Буква: `font-size: min(40dvh, 55vw)`, `line-height: 1`. Единица `dvh` — та же,
  что у контейнера, иначе буква считает высоту по спрятанному тулбару.
  Перед ней дублирующее правило с `vh` как фолбэк для Safari до 15.4.
- Кнопки: минимальная высота 72px, крупный шрифт, `touch-action: manipulation`
  (убирает задержку 300 мс и зум по двойному тапу).
- `user-select: none` на всём приложении — чтобы ребёнок не выделял текст.
- `padding` с учётом `env(safe-area-inset-*)` со всех четырёх сторон. Низ — под
  индикатор home; боковые — потому что при `viewport-fit=cover` в ландшафте на
  iPhone с вырезом горизонтальные отступы доходят до ~44px, и без них верхняя
  строка и края кнопок уезжают под вырез и скруглённые углы.
- `overflow: hidden` на `body`: фолбэк `height: 100%` на iOS считается от малого
  вьюпорта, а `.app` — от `100dvh`. Когда они расходятся, страница становится
  прокручиваемой на высоту тулбара — пустая полоса и резиновый отскок под пальцем.
- Смена буквы: fade-in 150 мс, чтобы переход был заметен. Больше анимаций нет.
- Темы: CSS-переменные, переключаются атрибутом `data-theme` на `<html>`.
  Светлая — тёмный текст на почти белом; тёмная — светлый текст на почти чёрном.
  Полный набор переменных определён на `:root`; блок `[data-theme="dark"]`
  переопределяет только цвета.
- Шрифт: системный стек (`system-ui, -apple-system, "Segoe UI", Roboto,
  sans-serif`) — кириллицу покрывает, вес файла не растит.
- `<meta name="viewport" content="width=device-width, initial-scale=1,
  viewport-fit=cover">`.
- Переключатель RU/EN — два текстовых элемента, активный контрастный,
  неактивный приглушённый. Переключатель темы — один символ (☼ / ☾).

## `build.py`

Без зависимостей, стандартная библиотека.

1. Прочитать `src/index.html`.
2. Заменить строку `<link rel="stylesheet" href="styles.css">` на
   `<style>` + содержимое `src/styles.css` + `</style>`.
3. Заменить строку `<script type="module" src="app.js"></script>` на
   `<script>` + бандл + `</script>`.
4. Бандл — конкатенация в фиксированном порядке: `alphabets.js`,
   `scheduler.js`, `app.js`. Порядок задан списком в `build.py`.
5. При конкатенации: выбросить строки, начинающиеся с `import `, и убрать
   префикс `export ` в начале строки.
6. Проверки, каждая падает с внятной ошибкой:
   - в результирующем бандле не осталось `import`/`export`/`require`;
   - в бандле нет подстроки `</script>`;
   - в `src/index.html` нашлись обе строки-плейсхолдера (2 и 3).
7. Записать `dist/index.html`, напечатать итоговый размер в килобайтах.

Ограничение, принятое сознательно: инлайнинг работает только для простых
статических импортов из локальных файлов и фиксированного порядка модулей.
Динамические `import()` в проекте не используются.

### Разработка

`src/index.html` открывается в браузере напрямую только через сервер —
`file://` блокирует ES-модули:

```
python3 -m http.server 8000 -d src
```

Итоговый `dist/index.html` открывается по `file://` без проблем — в нём нет
модулей.

## Тесты

`node --test` из корня проекта — именно так, без аргумента. Зависимостей нет.
На Node 25 `node --test tests/` падает: Node пытается резолвить `tests`
как модуль, а не рекурсивно обходить каталог.

### `tests/scheduler.test.js` (17 тестов)

1. Буква, которой нет в истории, получает `t = 300`, `k = 1`, `w = 300`.
2. Буква из `lastShown` получает `t = 0` и `w = 0`.
3. `lastShown` даёт `w = 0`, даже если буква есть в `history`.
4. Ответ «знаю» даёт `k = 0.5`, «не знаю» — `k = 2`.
5. `t` растёт со временем: для одной и той же истории при большем `nowMs`
   вес больше.
6. В начале сессии все веса равны между собой.
7. `recordAnswer` записывает `answer` и `closedAt` в `history` и выставляет
   `lastShown`.
8. `recordAnswer` для уже отвеченной буквы перезаписывает её запись.
9. `pickNext` при `rng = () => 0` возвращает первую букву с ненулевым весом.
10. `pickNext` при `rng = () => 0.999999` возвращает последнюю букву
    с ненулевым весом.
11. `pickNext` никогда не возвращает `lastShown` (прогон по многим значениям
    `rng` на маленьком алфавите).
12. `pickNext` на алфавите из одной буквы возвращает эту букву, не зацикливаясь
    и не возвращая `undefined`.
13. Статистический прогон: на алфавите из трёх букв с разными весами
    прогнать `pickNext` 10 000 раз с детерминированным ГПСЧ (LCG с
    зафиксированным зерном, определён прямо в тесте) и убедиться, что
    эмпирические частоты совпадают с расчётными `w / Σw` с допуском 0.02.
    Веса подобраны так, чтобы частоты были 0.30 / 0.20 / 0.50 — минимальный
    зазор впятеро больше допуска. Ожидаемые частоты записаны литералами,
    а не вычисляются через `computeWeights`: иначе сломанная формула весов
    подставит одинаково сломанное ожидание и тест не сможет упасть.
14. Буква из `lastShown` получает `k = 1`.
15. Скатывание с конца цикла из-за погрешности возвращает последнюю букву
    с ненулевым весом (`rng` возвращает ровно `1`).
16. При `Σw = 0` выбор равномерный и действительно использует `rng`.
17. Часы, переведённые назад (`closedAt > nowMs`): все веса равны `0`,
    не отрицательны, а `pickNext` возвращает букву из массива, не `null`.

### Ручная проверка UI

Автотестов на UI нет — проверяется руками по списку:

- открыть `dist/index.html` по `file://` — работает без сети и без сервера;
- таймер идёт `5 → 1` и исчезает на нуле;
- нажатие любой кнопки меняет букву и перезапускает таймер;
- одна и та же буква не выпадает дважды подряд;
- переключение RU/EN меняет алфавит немедленно;
- тумблер темы переключает цвета;
- алфавит и тема сохраняются после перезагрузки, история ответов — нет.
  На `file://` это может не сработать: Safari исторически бросает `SecurityError`
  на `localStorage` для локальных файлов. Приложение к этому готово (каждое
  обращение в `try/catch`), но тогда настройки просто не запоминаются;
- на телефоне: нет горизонтального скролла, кнопки достаются большим пальцем,
  двойной тап не зумит, по тапу нет серой вспышки;
- поворот в ландшафт: буква и кнопки помещаются, ничего не уезжает под вырез;
- страница не прокручивается и не отскакивает под пальцем.

- после деплоя новой версии: первое открытие может показать старую, со
  следующего запуска — новая.

## Что сознательно не делаем (YAGNI)

- Нет звука и озвучки букв.
- Нет статистики, прогресса и экрана результатов.
- Нет сохранения истории ответов между запусками.
- Нет системной темы (`prefers-color-scheme`) — только ручной тумблер.
- Нет строчных букв и случайного регистра.
- Нет настройки длительности таймера.
- Нет других алфавитов, кроме RU и EN.
- Переключатели в верхней строке намеренно мелкие (~28×24px, меньше рекомендуемых
  44px). Это контролы родителя, к ним обращаются редко, а случайное попадание
  ребёнка по переключателю алфавита посреди занятия хуже, чем редкий промах
  взрослого. Кнопки ребёнка при этом полноразмерные — 72px.
- Нет защиты от частых нажатий (debounce) на кнопках ответа: по спеке нажимает
  взрослый.
- Нет `color-scheme` и `<meta name="theme-color">`. У `body` задан явный фон,
  который распространяется на канву вьюпорта, поэтому зона отскока и так тёмная;
  форм-контролов и областей прокрутки в приложении нет. `theme-color` пришлось бы
  переписывать из JS на каждом переключении темы — заметная цена за косметику.
- `<html lang>` не меняется при выборе EN: влияет только на речь и переносы,
  а весь текст интерфейса остаётся русским.
