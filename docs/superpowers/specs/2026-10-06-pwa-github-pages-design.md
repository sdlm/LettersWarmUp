# PWA и GitHub Pages — дизайн

Дата: 2026-10-06

Развивает намерение из `docs/pwa-and-github-pages.md` и закрывает его
нерешённые вопросы.

## Цель

Приложение можно установить на телефон и запускать без сети:

1. Открыть `https://sdlm.github.io/LettersWarmUp/` и добавить на главный экран.
2. Дальше приложение стартует с иконки, без адресной строки, экран не гаснет.
3. После первого открытия всё работает в самолётном режиме.

`dist/index.html`, открытый с диска по `file://`, ведёт себя ровно как сегодня.

## Ключевые решения

| Вопрос | Решение |
|---|---|
| Сколько HTML на выходе | Один `dist/index.html`. PWA-части включаются только по `http(s)` |
| Иконка | Генерируется разовым скриптом, PNG коммитятся в `src/icons/` |
| Ориентация | Не фиксируется |
| `theme-color` | Переписывается из JS при смене темы: `#ffffff` / `#0b0b0b` |
| Стратегия кеша | Cache-first для всей оболочки, имя кеша содержит хеш содержимого |
| Обновление | `skipWaiting` + `clients.claim`; новая версия видна со следующего запуска |
| Деплой | GitHub Actions выкладывает закоммиченный `dist/` как есть |

## Структура файлов

Новое и изменённое:

```
src/
  index.html               + <link rel="manifest">, apple-touch-icon, theme-color, мета для iOS
  app.js                   + регистрация SW, Wake Lock, обновление theme-color
  manifest.webmanifest     новый
  sw.js                    новый, шаблон с плейсхолдером версии кеша
  icons/
    icon-192.png           новый, коммитится
    icon-512.png           новый, коммитится
    apple-touch-icon.png   новый, 180×180, коммитится
tools/
  make_icons.swift         разовый генератор иконок, в сборке не участвует
build.py                   + копирование ассетов, генерация sw.js, проверки
.github/workflows/pages.yml  новый
dist/
  index.html
  manifest.webmanifest
  sw.js
  icon-192.png, icon-512.png, apple-touch-icon.png
```

Все URL в манифесте, SW и разметке относительные (`./…`), потому что сайт живёт
в подпапке `/LettersWarmUp/`.

## `manifest.webmanifest`

- `name`: «Алфавит», `short_name`: «Алфавит», `lang`: `ru`
- `start_url`: `./`, `scope`: `./`
- `display`: `standalone`
- `background_color` и `theme_color`: `#ffffff` (стартовая тема светлая)
- `icons`: 192 и 512, `purpose: "any"`. Отдельную maskable-иконку не делаем:
  фон иконки сплошной, поля достаточные, Android обрежет её аккуратно.
- `orientation` не задаётся.

## Разметка `src/index.html`

Добавляется в `<head>`:

```html
<meta name="theme-color" content="#ffffff">
<link rel="manifest" href="manifest.webmanifest">
<link rel="apple-touch-icon" href="apple-touch-icon.png">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-title" content="Алфавит">
```

По `file://` эти ссылки ведут в никуда или игнорируются: браузер максимум
напишет в консоль про недоступный манифест. На работу приложения это не влияет.

Якорные строки, на которые опирается `build.py`, не меняются.

## `sw.js`

Исходник `src/sw.js` содержит строку `const CACHE_VERSION = "__CACHE_VERSION__";`
и список файлов оболочки:

```
./
./index.html
./manifest.webmanifest
./icon-192.png
./icon-512.png
./apple-touch-icon.png
```

Поведение:

- **install**: открыть кеш `letters-warmup-<CACHE_VERSION>`, положить в него весь
  список, затем `self.skipWaiting()`.
- **activate**: удалить все кеши с префиксом `letters-warmup-`, кроме текущего,
  затем `self.clients.claim()`.
- **fetch**: только `GET`. Ответ ищется в кеше (`ignoreSearch: true`); если он
  есть — отдаётся, иначе запрос уходит в сеть. Приложение не делает своих
  сетевых запросов, так что сетевой путь срабатывает только для того, чего в
  оболочке нет.

Следствие: после деплоя первое открытие ещё показывает старую версию и в фоне
ставит новую; со следующего запуска видна новая. Для этого приложения это
приемлемо, уведомление «доступно обновление» не делаем.

## `app.js`

Три небольшие добавки, каждая молча ничего не делает там, где API недоступен.

**Регистрация SW.** При старте, если `"serviceWorker" in navigator` и
`location.protocol` — `http:` или `https:`, вызвать
`navigator.serviceWorker.register("sw.js")`. Отказ промиса ловится и
игнорируется.

**Wake Lock.** Если есть `navigator.wakeLock`, запросить `request("screen")` при
старте и повторно на `visibilitychange`, когда документ снова виден (браузер
снимает блокировку при уходе в фон). Ошибки (нет secure context, батарея,
отказ) ловятся и игнорируются. По `file://` API недоступен — ветка не
выполняется.

**theme-color.** `applyTheme` дополнительно выставляет `content` у
`<meta name="theme-color">` в `#ffffff` или `#0b0b0b`. Если мета не найдена,
ничего не делает. Цвета дублируют `--bg` из `styles.css`; это две строки, общий
источник ради них не заводим.

## Иконки

`tools/make_icons.swift` — разовый скрипт на AppKit (Swift на машине есть,
зависимостей не нужно). Рисует «Аа» крупным жирным системным шрифтом по центру
квадрата со сплошным цветным фоном и сохраняет три PNG в `src/icons/`. Запуск:
`swift tools/make_icons.swift`. Результат коммитится; `build.py` только
копирует готовые файлы. Если иконку захочется поменять — правится скрипт и
перезапускается вручную.

## `build.py`

К текущей сборке `dist/index.html` добавляется:

1. Скопировать `src/manifest.webmanifest` и `src/icons/*.png` в корень `dist/`.
2. Посчитать SHA-256 по содержимому всех файлов `dist/` кроме `sw.js`
   (в фиксированном порядке имён) и взять первые 12 hex-символов.
3. Прочитать `src/sw.js`, заменить `__CACHE_VERSION__` на хеш, записать
   `dist/sw.js`.

Новые проверки, по стилю как существующие (`SystemExit` с объяснением):

- в `src/sw.js` плейсхолдер `__CACHE_VERSION__` встречается ровно один раз;
- каждый файл из списка оболочки в `sw.js` (кроме `./`) существует в `dist/`;
- в собранном `index.html` есть `<link rel="manifest"`.

Список оболочки `build.py` вытаскивает из `src/sw.js` регуляркой по строкам
вида `"./…"`, чтобы список жил в одном месте.

## Деплой

`.github/workflows/pages.yml`: на `push` в `main` и вручную (`workflow_dispatch`).
Шаги: `actions/checkout`, `actions/configure-pages`,
`actions/upload-pages-artifact` с `path: dist`, `actions/deploy-pages`.
Права: `pages: write`, `id-token: write`. Сборки в CI нет: `dist/` уже
закоммичен, как и раньше.

Pages включается один раз через
`gh api -X POST repos/sdlm/LettersWarmUp/pages -f build_type=workflow`.

Риск: если забыть запустить `build.py` перед коммитом, задеплоится старый
`dist/`. Так же обстоит дело и сейчас с файлом для телефона; проверку
актуальности в CI не добавляем.

## Тесты

Логика добавок — обращения к браузерным API, юнит-тестами её не покрыть
осмысленно; существующие `node --test` должны остаться зелёными.

### Проверка перед деплоем (локальный сервер)

`python3 -m http.server -d dist`, затем в браузере на `http://localhost:8000/`:

- манифест распознан, ошибок в консоли нет;
- service worker активен, в кеше все шесть записей;
- в DevTools включить offline, перезагрузить — приложение открывается и
  работает;
- `dist/index.html`, открытый по `file://`, работает и не пишет ошибок кроме
  возможного предупреждения про манифест.

То же на живом URL после первого деплоя.

### Ручная проверка на телефоне (дополнение к чек-листу в основной спеке)

- Android/Chrome: «Установить приложение», иконка на главном экране.
- iOS/Safari: «На экран Домой», иконка не пустая.
- Запуск с иконки — без адресной строки.
- Самолётный режим, запуск с иконки — работает.
- Экран не гаснет минуту с лишним без касаний.
- Переключение темы меняет цвет системной панели (Android).
- Тема и алфавит переживают перезапуск.

## Что сознательно не делаем

- Отдельную PWA-копию `dist/pwa/`.
- Уведомление о новой версии и кнопку «обновить».
- Фиксацию ориентации.
- Maskable-иконку и набор иконок под все размеры.
- Сборку или проверку актуальности `dist/` в CI.
