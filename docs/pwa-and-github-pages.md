# Намерение: PWA-обвязка и выкладка на GitHub Pages

**Статус:** реализовано, см. `docs/superpowers/specs/2026-10-06-pwa-github-pages-design.md`. Дальше — исходное намерение, сохранено как история.

Дата фиксации: 2026-09-10.

## Зачем

Сейчас приложение — один файл `dist/index.html`, который копируют на телефон и
открывают с локального диска. Это работает, но у способа есть цена:

- открывать html через файловый менеджер на Android неудобно, а на iOS ещё и
  капризно: превью в Файлах непредсказуемо относится к JavaScript;
- браузерная обвязка (адресная строка, вкладки) съедает вертикаль на экране,
  где главный элемент — огромная буква;
- экран гаснет через минуту бездействия, а занятие с ребёнком идёт дольше;
- `localStorage` по `file://` работает не везде — Safari исторически бросает
  `SecurityError`, из-за чего тема и алфавит не запоминаются.

PWA закрывает всё четыре пункта: иконка на домашнем экране, запуск в
`standalone` без хрома, Wake Lock для экрана и нормальный HTTPS-origin со
работающим хранилищем.

## Ключевое ограничение

**`dist/index.html` должен продолжать работать по `file://` после этих изменений.**

Это исходное требование проекта («завернуть в один файл, чтобы удобно кинуть на
телефон»), и PWA его не отменяет, а дополняет. Открытый с диска файл просто не
активирует PWA-обвязку и ведёт себя ровно как сегодня.

## Структурное следствие для сборки

Service worker нельзя вшить в HTML — браузер регистрирует его только как
отдельный файл по URL, и от пути этого файла зависит scope. Иконки манифеста
тоже практичнее держать настоящими файлами, чем `data:`-URI (поддержка
последних непоследовательна).

Значит, сборка перестаёт производить ровно один артефакт и начинает
производить два:

```
dist/
  index.html          один файл для file:// — как сейчас, без изменений
  pwa/
    index.html        то же приложение + регистрация SW + <link rel="manifest">
    manifest.json
    sw.js
    icon-192.png
    icon-512.png
```

`build.py` придётся расширить, чтобы он собирал обе цели. Его текущие проверки
(якорные строки, отсутствие `import`/`export`, отсутствие `</script>`) остаются
осмысленными для обеих.

## Что нужно сделать

1. **`manifest.json`** — `name`, `short_name`, `start_url`, `display: standalone`,
   `background_color`, `theme_color`, иконки 192 и 512 px.
2. **Иконки** — нарисовать. Их пока нет, и это единственная часть работы, которая
   не сводится к коду.
3. **`sw.js`** — cache-first для оболочки приложения. Приложение полностью
   статично и не ходит в сеть, поэтому кеш тривиален: список из пяти файлов.
   Нужна стратегия инвалидации при обновлении (версия в имени кеша).
4. **Регистрация SW** в PWA-варианте `index.html`, обёрнутая так, чтобы её
   отсутствие по `file://` не было ошибкой.
5. **Wake Lock** — `navigator.wakeLock.request("screen")`, с повторным захватом
   по `visibilitychange` (блокировка теряется при уходе вкладки в фон). Требует
   secure context, то есть достаётся только PWA-варианту. По `file://` — тихо
   пропускать.
6. **GitHub Pages** — включить для репозитория, деплоить содержимое `dist/pwa/`.
7. **Дополнить ручной чек-лист** в спеке проверками для PWA-варианта: установка
   на домашний экран, запуск без адресной строки, работа в самолётном режиме
   после первой установки, экран не гаснет.

## Принятые к сведению компромиссы

- **Способ доставки меняется.** Было: скопировал файл. Станет: закоммитил,
  дождался деплоя, обновил страницу. Появляется шаг выкладки там, где было
  перетаскивание. Вариант с одним файлом при этом остаётся доступен.
- **Первая установка требует сети.** Дальше SW кеширует и оффлайн работает, но
  сценарий «достал телефон без симки и открыл» покрывается только
  `file://`-вариантом.
- **Бесплатный GitHub Pages работает только для публичного репозитория.**
  Приложение станет доступно по адресу вида `username.github.io/LettersWarmUp`.
  Для алфавита это безобидно, но репозиторий придётся открыть — либо взять
  GitHub Pro ради приватного.

## Нерешённые вопросы

- `theme_color` в манифесте статичен, а тема в приложении переключается в
  рантайме. Красить под светлую, под тёмную или переписывать `<meta name="theme-color">`
  из JS на каждом переключении? В дизайне мы `theme-color` уже отклоняли как
  «заметная цена за косметику» — в PWA расклад может измениться, потому что
  там это цвет системной панели, а не строки браузера.
- Фиксировать ли `orientation`. Ландшафт у нас самый тесный по вертикали;
  портретный лок упростил бы вёрстку, но может раздражать.
- Нужен ли вообще отдельный `dist/pwa/index.html`, или разумнее оставить один
  HTML, а регистрацию SW сделать безусловной с мягкой обработкой отказа.
  Решается на этапе дизайна.
- Кто рисует иконки.

## Рассмотрено и отклонено

- **APK-обёртка над WebView.** Работает, полный оффлайн, хостинг не нужен. Но на
  машине нет ни JDK, ни Android SDK, ни Studio — это ~10 ГБ загрузок и возня с
  лицензиями SDK ради тридцати строк кода. Отдельная ловушка: в Android WebView
  `localStorage` выключен по умолчанию, без `setDomStorageEnabled(true)`
  настройки перестанут запоминаться, и это будет выглядеть как баг приложения.
  Держим как запасной вариант, если PWA почему-то не подойдёт.
- **Capacitor / Cordova.** Притащат целое npm-дерево в проект, где сейчас ноль
  зависимостей, а дадут ровно то же, что APK-обёртка.
- **Публикация в Play Store.** $25 за аккаунт, ревью, политика
  конфиденциальности, требования к target API. Для приложения, которым
  пользуется один ребёнок, сайдлоад решает ту же задачу бесплатно.
